# Aviation Theory VR - Technical Documentation

## 1. ModuleActivityScheduler & Activity Integration

### Overview
The `ModuleActivityScheduler` (MAS) serves as the central orchestrator for all interactive tasks within a module. It bridges the gap between static instructional data (ScriptableObjects) and dynamic gameplay logic (Scripts like `TiltController`).

### The Data Layer: ModuleActivities.cs
Activities are defined as `ScriptableObjects`. Each asset contains:
- **Instructions**: An array of strings displayed to the user.
- **customScript**: A reference to a Prefab that contains the logic for the activity.
- **totalSteps**: How many external signals the MAS expects before the activity is considered complete.

### The Runtime Lifecycle (The "Handshake")

1. **Activation**: The `ModuleManager` triggers `MAS.StartActivity(newActivity)`.
2. **Instantiation**: MAS checks if the activity asset has a `customScript` prefab. If so, it instantiates it into the scene.
3. **Interface Call**: MAS searches the instantiated object for any component implementing `IActivityController`. It then calls `controller.StartActivity()`.
4. **Logic Execution**: The custom script (e.g., `TiltController`) begins monitoring user input (like controller tilt).
5. **Signaling Progress**: When the user performs the required action, the custom script calls:
   `ModuleActivityScheduler.Instance.OnExternalStepCompleted();`
6. **State Synchronization**: MAS receives this call and updates the UI.
7. **Completion & Cleanup**: MAS calls `Destroy(activeControllerObject)` and signals the `ModuleManager`.

## 2. TiltController.cs

### Overview
The `TiltController` is a specialized "Adapter" script. It monitors VR controller rotation and signals the `ModuleActivityScheduler` when a specific tilt threshold is met.

### Key Features
- **Neutral Capture**: Captures the initial rotation 0.1s after `StartActivity()` to ensure relative movement detection.
- **Angle Normalization**: Converts Unity's 0-360 angles to -180 to 180 for reliable threshold checking.
- **Automatic Hinting**: Can automatically find and enable a `ControllerHint` in the scene.

---

## 3. ControllerHint.cs

### Overview
Provides a lightweight, code-driven animation to show the user the required movement.
- **Animation**: Uses a Sine-wave oscillation (`Mathf.Sin`) to rock a controller model.
- **Clean State**: Automatically resets the model rotation on `OnDisable` to ensure visual consistency.

## 4. DA_40.cs (Diamond DA40 Aircraft)

### Overview
Central hub for the aircraft model. Manages parts, sounds, and the propeller.

### Propeller Implementation
- **LateUpdate Rotation**: Applied in `LateUpdate` to ensure it isn't overwritten by the plane's `Animator`.
- **Dynamic Speed**: Uses `Mathf.MoveTowards` for smooth acceleration/deceleration.

## 5. ProceduralAirflow.cs (Force Arrows & Labels)

### Overview
The `ProceduralAirflow` script handles the visual representation of aerodynamic forces, the Centre of Pressure (COP), and the procedural airflow particle system.

### Force Arrows Implementation
The script procedurally generates and scales four arrows representing the primary flight forces:
- **Lift** (Green)
- **Weight** (Red)
- **Thrust** (Blue)
- **Drag** (Yellow)

**Key Logic:**
1. **Procedural Construction**: Arrows are built at runtime using a Cube primitive for the shaft and a provided mesh for the head (`arrowHeadModel`).
2. **Dynamic Scaling (AoA)**: The length of the arrows is NOT static. It depends on the aircraft's **Angle of Attack (AoA)**. The script uses a lookup table (`aoaStages`) and parallel arrays (`liftValues`, `dragValues`, etc.) to linearly interpolate (`Mathf.Lerp`) the force magnitude based on the plane's pitch.
3. **Anchors**: Arrows are attached to specific `Transform` anchors on the aircraft model (e.g., `liftAnchor`) to ensure they stay pinned to the correct part of the airframe.

### Arrow Labels
Labels (e.g., the word "LIFT") are implemented using **TextMeshPro**:
1. **Billboarding**: Each label object has a `Billboard` component attached, which forces the text to always face the player's camera.
2. **Occlusion Prevention**: To prevent the aircraft's 3D mesh from hiding the text, the script calculates a vector from the label to the camera and pushes the label 0.5 units along that vector in `SetArrow()`. This ensures the text "pops" in front of the aircraft from the player's perspective.

## 6. StallVisualTrigger.cs (found in stall_airflow.cs)

### Overview
Directly "hacks" the `GhostTrail` particle system during stall events.
- **Logic**: Intercepts particles in `LateUpdate` and injects upward velocity/acceleration.
- **Result**: Visualizes the loss of control as a dramatic upward "swoop" in the trajectory trail.
